感知層與理解層模型選型

三家官方文件查完的結論：感知層（語音辨識）選 Gemini，理解層（把話變成點餐指令）照老闆決定用 Gemini。Claude 沒有語音輸入，不進感知層。三個決定連同「社守 POS、先做大德」一併記入藍圖。

2026-09-28資料來源：三家官方文件（連結在頁尾）匯率估算 1 USD ≈ NT$32

1. 結論先講

感知層 · 選用

Gemini 3.5 Transcribe Live

串流語音辨識專用模型。有「暫定字幕＋定稿」兩段輸出、自訂詞庫最多 1,000 詞、伺服器＋店內混合斷句，每分鐘約 US$0.009，三家最便宜。

條件：第 0 階段用 200 句真實對話評測，台灣國語命中率 ≥ 90% 才定案。

感知層 · 備援

GPT gpt-live-transcribe

功能同級，官方明列支援 zh-tw、cmn、yue；關鍵詞提示、可調延遲。每分鐘 US$0.017，約 Gemini 的 1.9 倍。Gemini 評測沒過就切這條，程式介面設計成可抽換。

感知層 · 不採用

Claude

Claude API 沒有語音輸入。官方範例都是接 Deepgram／ElevenLabs 先轉文字再給 Claude，等於要多買一家。不進感知層；可留在離線對帳與評測當第二意見。

理解層：依老闆決定採 Gemini 3.8 Flash 做「直覺式判斷」——每句話一次呼叫、結構化輸出點餐指令、菜單放在 context cache。感知與理解同一家，一組憑證、一份帳單、一個 SDK。

3. 這個選擇對架構的三個影響

說話者分辨要自己做

兩家串流辨識都不分誰在講。改在店內做：櫃台人員上班時錄 10 秒聲紋註冊，店內小電腦用聲紋比對把每句話標「櫃台／客人」，再送辨識。

10 分鐘上限反而剛好

一組客人點餐平均 1～2 分鐘。設計成「一組客人一條連線」：待命時預先開好一條，客人開口就用，結束即關；永遠不會碰到 10 分鐘。8 小時待命不靠一條長連線撐。

繁簡轉換與評測是必做

Gemini 輸出可能是簡體，加一層 OpenCC 轉繁體（毫秒級）。真正的風險是台灣國語與台語命中率，只有第 0 階段的 200 句評測能回答，這是選型的最後一關。

4. 理解層：Gemini 3.8 Flash 直覺式判斷

輸入

最新一句 ＋ 草稿單摘要

只給「誰說的、說了什麼」與目前草稿單的編號清單，不給整段歷史。

→
固定知識（快取）

菜單主庫 ＋ POS 選項群組

放 context cache，每小時儲存費約 US$0.003，呼叫時讀取價只有輸入價的 1/10。

→
模型

gemini-3.8-flash

不開延伸思考、單次呼叫、結構化輸出（JSON schema）。目標 < 800 ms。

→
輸出

1～3 條指令

add / remove / set_qty / set_option / replace，每條帶信心分數與對應的草稿單編號。

項目設計
「直覺式」的意思不做多步推理、不查資料、不回頭讀整段對話。一句話進、指令出，錯了下一句會修正，核對階段再總校對。
核對階段的總校對櫃台開始複誦時，改用同一模型但開延伸思考，把整段對話與草稿單一次比對，找出前面漏掉或衝突的項目。一單只跑一次。
價格（官方 2026 年內）輸入 US$0.75／百萬 token、輸出 US$3.75／百萬、快取讀取 US$0.075／百萬（2027 起翻倍）
每天估算200 單 × 約 10 次呼叫 ≈ US$2（NT$65）；含核對總校對約 NT$80
Claude 的位置不在即時路徑上。每日下班後用 Claude 重跑當天文字稿做第二意見對帳，量出 Gemini 的漏判率——這是判斷理解層要不要換模型的證據來源。

6. 社守 POS（GeoShop）對出單層的意義

已經有後台 API 經驗

成本系統的 P2 爬蟲已改成「HTTP API 直取」GeoShop 後台銷售資料，兩店各一組憑證、欄位（o_aid / sta / ppl / qan / pc_n / menu[]）都摸清了。讀的那一端不用從零開始。

官方有「線上訂單自動接收」

社守對外宣傳搭配 Uber Eats 串接、線上點餐訂單自動進 POS。這表示 POS 有一條「外部訂單進入」的通道——這條通道就是藍圖第 7 節的方式 A，要問社守能不能給我們用。

要問社守的兩個問題

  • 外部訂單匯入的介面（API 或線上點餐後台）能否開給自家系統？格式與費用？
  • 如果不能，前台平板有沒有「待確認訂單」或掛單功能可以塞草稿單？

客服 04-26312051（成本系統文件記載）。

老闆要匯出的「POS 前台平板點餐架構」正是這裡最需要的東西。最好的形式：分類 → 品項 → 選項群組 → 選項值的完整樹（Excel／CSV／截圖都可以），加上套餐（+蛋+飲料）與加購的打法。有了它，理解層的菜單知識與出單層的格式轉換可以一次定案。
